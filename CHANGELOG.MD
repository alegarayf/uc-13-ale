- **`pytest.ini` comma bug**: `pythonpath = databricks, .` was parsed by pytest's `pythonpath` ini option (a whitespace/newline-delimited linelist, not a comma-separated string) as two broken tokens — a literal, non-existent `databricks,` directory and `.` — silently leaving `databricks/` off `sys.path` when a test file was collected before some other test's incidental `sys.path.insert(...)` masked the bug. Root cause of `tests/test_golden_checklist_elder_care.py`'s collection failure in isolation (works in the full suite today only because another test file happens to mutate `sys.path` first — an order-dependent latent bug). Fixed to a proper multi-line `pythonpath` list.
- **New root `conftest.py`**: stubs `pyspark` (types, `SparkSession`, `Row`, `pyspark.sql.utils.AnalysisException`) when the real package isn't installed, with each scalar/complex type as a genuinely distinct class (not one shared stand-in) so `isinstance`-based dispatch in production code (e.g. `eval/retrieval/scripts/apply_ops_ddl.py::_spark_type_to_ddl`) works correctly. Lives at repo root (not nested under `tests/` or `eval/retrieval/tests/`) so it loads before any test module regardless of collection order — closes both the `ImportError: cannot import name 'DoubleType'` (an incomplete, narrower stub embedded in one M-PHV1 test file was accidentally the only thing providing `pyspark.sql.types` when collected first) and the `ModuleNotFoundError: pyspark.sql.utils` collection error in `eval/retrieval/tests/test_apply_ops_ddl_migration.py`.
- **`eval/retrieval/store.py::SqliteEvalStore.get_latest_baseline`**: added `rowid DESC` as a secondary `ORDER BY` key after `completed_at DESC`. `completed_at` timestamps are wall-clock (`datetime.now(timezone.utc)`) with no artificial spacing between test-fixture finalize calls; on a fast machine two calls can tie at the stored ISO-string's precision, and SQLite's tie-break for equal sort keys is not guaranteed to favor the later-inserted row. This was a genuine (if narrow) correctness bug, not just test flakiness — the query's contract is "most recently completed," and ties should resolve toward the most recent insert. Fixes `test_get_latest_baseline_returns_most_recent_complete` (re-run 5× to confirm).
