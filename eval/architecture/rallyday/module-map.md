**Notes**

- `databricks/` UC13 pipeline and the Garden app (`frontend` + `backend-*`) share the repo but deploy independently; coupling is via Unity Catalog tables and env config, not imports. `[needs confirmation]` on whether UC13 analysis outputs will surface in the Garden UI.
- **Dual orchestration model (post hector-ui-pipeline-merge):** `agents.orchestration` runs the diligence DAG (Phase 3→5) and writes `analysis.diligence_report`; `agents.exec_summary` builds the Rainmaker Rev3 one-pager + full report from completed agent outputs via `build_exec_summary()`. They are composed sequentially in `run_full_pipeline.py` / `run_vdr_pipeline.py`, not merged into one orchestrator class.
- **T1 rename (2026-07-24):** `agents.orchestrator` → `agents.exec_summary`. Notebook and tests assert zero surviving `agents.orchestrator` imports in active paths (`tests/test_notebook_symbol_references.py`).
- **sqlite→Delta provenance (2026-07-27):** `open_agent_run(spark=)` binds `DeltaEvalStore` on worker threads; `resolve_store()` fail-closed when `RE2_STORE_BACKEND=delta` without Spark. All 7 instrumented agent `main()` + profiler pass `spark=`.
- **Eval harness M1–M4 (2026-07-21):** Golden checklists for BMA/CQA/KPI/QoE/Profiler; `evaluate_promotion` gate; `.dev/scorecards/` INDEX with Elder Care baselines. Program `uc13-eval-harness-all-agents` complete.
- **Rainmaker Rev3 (2026-07-22):** Compressed template restructure (`thesis_bullets`, `key_watchouts`, `workforce_notes`); Elder Care validation ACCEPT at 1,344 words.
- **Post-merge regressions (2026-07-28):** BMA Haiku truncation + `flags` JSON string parse fixed; parallel DAG e2e `run_id=1074138209208842` — 9 SUCCESS / 0 FAILED. See `post_merge_regressions.md`.
- SQL DDL references `garden.rules`; runtime table ref in `backend-api` uses `{DATABRICKS_CATALOG}.{DATABRICKS_SCHEMA}.rules`. `[needs confirmation]` that catalog/schema are always set to `garden` in production.
- **Catalog convention:** production scripts default `uc13`; eval/notebook/harness use `uc13_ale` — `tests/test_catalog_convention.py` is PG3 gate.
- **M-PHV4 retrieval consolidation (2026-07-15):** `_TYPE_ORDER` dedup, FTA+harness fallback unification, R-08 join integrity; item 29 (`vs_metadata_filters` default flip) **not activated**.
- **M0–M4 incremental ingestion refactor (2026-08-05/06, `.dev/company-analysis-diff-pre-vs-post-refactor.md`, `ingest-completeness-notes.md`):** Whole-company DELETE+APPEND replaced by per-doc resumable ingest — `parse_manifest.ParseManifest.build()` produces the work list, `doc_worker.DocWorker` claims/parses/embeds one doc at a time and writes `{catalog}.ingestion.doc_status` (via `status_store.py`), and `sync_state.py` gates VS Delta Sync behind a watermark so it only re-runs after new COMPLETE rows. Canonical doc identity moved out of `ingestion_parser.py` into `doc_id.make_doc_id(catalog, schema, company, folder_path, file_name)`; `retrieval.py`'s `chunks`↔`doc_relevance` join key changed from `(file_name, company_name)` to `doc_id`, requiring `doc_id` populated on both tables (`document_classifier.py` backfills via `_backfill_missing_doc_ids`). Elder Care ingest completeness rose 44.5%→98.3%, SPG 88.7%→100%. `uc13_ale` VS index gap remains open infra debt.
- **CIM-first VDR Rainmaker POC (2026-08, `vdr_rainmaker_poc.yml`):** `run_vdr_rainmaker.py` is a sibling to `run_vdr_pipeline.py` — reads the same `companies_vdr_history` trigger row, but detects/selects the CIM only (`cim_detection.py`), runs a scoped ingest + Phase 3–4 (no orchestrator memo) against sandbox catalog **`uc13_preview`** (not `uc13`), then renders an HTML/PDF one-pager (`rainmaker_view.py` deterministic view + `rainmaker_narrative.py` two bounded LLM calls, fail-open) via `renderers.render_rainmaker()`. Manual/POC trigger only — no UI wiring yet. Distinct from the production VDR path, which writes `.docx` from the full DAG + `build_exec_summary()`.
- **Eval program consolidation (2026-08, eval-consolidation M2–M4 + eval-multi-company-coverage-expansion M5):** New `eval/program/` governance layer (registry, product backlog, eval-debt ledger with high-water-mark ratchet, intent exemptions, onboarding queue) sits above `eval/retrieval/`'s measurement engine; new `eval/content/` package adds a three-rung content-correctness model (`deterministic` → `judge` → `human`) writing to `{catalog}.eval.s2_scores` (DDL: `databricks/ddl/s2_scores.sql`), rolled up by `eval/retrieval/trust_statement.py` into `eval/program/trust_statement.md`. Gold labels now cover four companies (`elder_care`, `clearsulting`, `gkf`, `spg`) via canonical slugs in `eval/retrieval/companies.py`; onboarding for new companies is driven by `eval/program/onboarding_queue.yaml` + `onboarding_runbook.md` + `onboarding_cluster_submit.py`.
