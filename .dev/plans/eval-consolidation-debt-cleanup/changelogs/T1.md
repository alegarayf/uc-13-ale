# T1 changelog — Fold enforcement across the `company_slug` parameter contract

- T1 (fold-guard enforcement for `company_slug`): added `require_folded_company_slug(company_slug: str) -> str` to `eval/retrieval/companies.py` (raises `PreconditionError` with message substring `company_slug must be canonical` when the value is not already in folded form, including non-str and fold-to-empty inputs; returns the value unchanged when it equals its own fold). Called it from the three previously-unguarded `company_slug` call sites — `eval/retrieval/gold/bootstrap.py::load_gold_exclusions` (guard runs on the raw parameter, before the existing `strip()`), `eval/retrieval/harness.py::default_gold_path` (which `EvalHarness.__init__`'s `company_slug` branch already delegates to, closing that third site transitively), and `eval/retrieval/harness_cli.py::main` where the previously-unguarded fold at the old line 121 was removed and replaced by folding `args.company_name` inside the existing `try` block (lines 96–100) alongside `EvalHarness(...)` construction, with the resulting `slug` reused for the summary line. This closes M4 rev 2 F-2-01, rev 1 F-15 (carried), and plan §8.4.3 T3 / O-2-2: an unfolded `company_slug` (e.g. `"Elder Care"`) can no longer silently pass through to a lookup-miss `{}` result or reach the filesystem-path-construction site, and an unnormalizable `--company-name` on the `--gold-path` CLI branch now fails before `EvalHarness.run(...)` is invoked rather than after a completed run. Placement in `companies.py` was chosen over `harness.py`/`bootstrap.py` because it is the only leaf module both call sites can import at module level without recreating the harness↔bootstrap import cycle (see decision log). Decision log: `.dev/plans/eval-consolidation-debt-cleanup/decision-logs/T1.md`.

## Adversarial test-coverage micro-pass

**Failure mode identified:** the three call sites named in the finding are `load_gold_exclusions`, `default_gold_path`, and `EvalHarness.__init__`'s `company_slug` branch. The frozen seven tests (§2.3) exercise the first two directly and the CLI path end-to-end, but none exercised `EvalHarness.__init__` itself with an unfolded slug — a regression that removed the `default_gold_path` call from `__init__` (while leaving `default_gold_path` itself guarded) would not have been caught by the frozen set.

**Action taken — added, not deferred.** Added `test_evalharness_init_rejects_unfolded_company_slug` to `eval/retrieval/tests/test_harness_fixture.py` (already in Files to touch), asserting `EvalHarness(company_slug="Elder Care")` raises `PreconditionError` matching `company_slug must be canonical`. This is a concrete falsifier for the identified gap: it fails if `EvalHarness.__init__`'s guard call path is ever severed from `default_gold_path`, independent of `default_gold_path`'s own direct test.
