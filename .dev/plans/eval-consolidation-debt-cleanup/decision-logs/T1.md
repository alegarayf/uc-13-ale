# T1 decision log — Fold enforcement across the `company_slug` parameter contract

## Chosen approach

Added a single module-level guard, `require_folded_company_slug(company_slug: str) -> str`, to `eval/retrieval/companies.py`. It returns the input unchanged when `canonical_company_slug(company_slug) == company_slug` (i.e. the value is already in canonical folded form), and raises `PreconditionError` with message substring `company_slug must be canonical` (plus the offending value rendered with `!r`) for any non-str input, any value that folds to something different, or any value that folds to empty (the latter case converts `UnnormalizableCompanySlugError` into `PreconditionError` so callers only need to catch one type at the guard boundary).

Called it from the raw parameter, before any `strip()`/normalization, at the three unguarded call sites:
- `eval/retrieval/gold/bootstrap.py::load_gold_exclusions` — guard inserted after the existing empty-check, before `slug = str(company_slug).strip()`.
- `eval/retrieval/harness.py::default_gold_path` — guard inserted as the function's first statement. `EvalHarness.__init__`'s `company_slug` branch calls `default_gold_path(company_slug)` directly, so this closes the third named call site (`EvalHarness.__init__`) without a separate edit to `__init__` itself.
- `eval/retrieval/harness_cli.py::main` — the fold previously at line 121 (after `harness.run(...)`, outside any `try`) was removed; `canonical_company_slug(args.company_name)` is now called inside the existing `try` block (lines 96–100) immediately after `EvalHarness(**_run_harness_kwargs(args))`, and its result (`slug`) is reused for the summary line. This is a plain `canonical_company_slug` call, not `require_folded_company_slug` — `main` folds a raw `--company-name` display name, it does not receive a pre-typed `company_slug` parameter, so the guard would be the wrong tool here; the actual fix is relocating the *existing* fold to run before side effects, per the packet's Fix locus 3.

## Alternatives rejected

- **Inline duplicated check at each of the three call sites** (no shared symbol). Rejected: three copies of the same three-line check drift independently under future edits, and it makes the M4 T13 "unknown slug → `{}`" vs. "unfolded slug → error" distinction (A-7) three separate places to get right instead of one.
- **`NewType` / validated wrapper type** (e.g. a `FoldedCompanySlug` newtype constructed once at the boundary). Rejected: it would touch the typed signatures of `load_gold_exclusions`, `default_gold_path`, and `EvalHarness.__init__` — none of which is licensed for a signature change per §2.1 ("Signature unchanged" is explicit for two of the three, and `EvalHarness.__init__` is not in Files to touch at all). A runtime guard achieves the same enforcement without any interface drift.
- **Hosting the guard in `harness.py` or `bootstrap.py`** instead of `companies.py`. Rejected per the packet's binding placement rule (§2.1): `harness.py` imports `bootstrap.py` at module level, and `bootstrap.py` imports `harness` only at function level to break that cycle; `companies.py` is a leaf (imports only `re`, now also `errors.py`, which imports nothing) and is the only module both call sites can import at module level.

## Assumptions made

- **A-5 (load-bearing):** `canonical_company_slug` is idempotent — `fold(x) == x` is a valid and sufficient test for "already folded." If this were false for some class of input, the guard would reject legitimate slugs at every production call site. Verified by the three-slug parametrized test (`elder_care`, `clearsulting`, `acme_corp`) and by the fact that `canonical_company_slug`'s body (companies.py:18-35) was not modified, so its behavior is unchanged from the prior milestone's verification.
- **A-7 (load-bearing):** M4 `decision-logs/T13.md`'s "well-formed but unknown slug → `{}`" contract is a distinct code path from "unfolded slug → error" and must not collapse. If `require_folded_company_slug` incorrectly treated an unregistered-but-folded slug (e.g. `"acme_corp"`) as invalid, `test_load_gold_exclusions_unknown_folded_slug_returns_empty` would fail — it does not (see changelog test evidence).
- **A-8:** `PreconditionError` is the correct envelope because (a) M4 rev 2 F-2-01 states the T13 contract text already claims it, and (b) `harness_cli.main` already catches `(PreconditionError, ValueError)` at the relevant `try` sites, so a guard raise degrades to a clean exit-1 with a stderr line rather than an uncaught traceback.
- Non-str input to `require_folded_company_slug` should raise `PreconditionError`, not `TypeError`, even though `canonical_company_slug` itself raises `TypeError` for non-str `name`. This keeps the guard's error surface uniform (one exception type) for callers that only need to catch `PreconditionError` at this boundary. No test in this plan currently calls the guard with a non-str value directly; the frozen test set exercises str inputs only (folded, unfolded, empty).

## Items deferred

- The O-2-1 function-level import convention in `bootstrap.py` (`from eval.retrieval.companies import ...` inside functions, not at module top) was preserved rather than hoisted to module level for the new `require_folded_company_slug` call, matching the file's three existing local imports of `canonical_company_slug`. Hoisting it is exactly the kind of drive-by cleanup the packet's non-goals section excludes (O-2-1 is explicitly named as out of scope); not revisited here.
- No other items deferred — both packet kill criteria and the adversarial micro-pass were satisfied within Files to touch.
